# SPAQ 结果

[English](../RESULTS.md)

个人研究试验。只有一个来源、一把尺子：SPAQ 手机照片感知质量，MOS 0–100。不要和 KonIQ 或其他量表平均。

## 切分和模型

Week 0 切分，种子 `image-jev-week0-v0.1`：训练 7,807，验证 1,660，测试 1,658。测试图不参与训练，也不参与选 checkpoint。

基座：`Qwen/Qwen3.5-2B`，NF4 4-bit，`max_pixels=65536`，视觉编码器冻结。指针档位是 0、10、……、100。报出的分数是 softmax 之后的期望档位。机器：NVIDIA RTX A2000 Laptop GPU，4 GB。

| 实验 | 训练了什么 | 测试用的 checkpoint |
| --- | --- | --- |
| 只训指针头 | 指针头，40 个 epoch，按验证损失取第 39 个 | 该 epoch |
| 语言 LoRA + 指针头 | 语言模型 LoRA r=8，外加指针头，1 个 epoch，976 步 | 最后一步 |
| 按验证损失选的 LoRA + 指针头 | 同一次训练，每 100 步在 256 张验证图上打分 | 第 900 步，再用全部 1,660 张验证图确认 |
| JSON QLoRA | LoRA r=8，1 个 epoch，生成 `{"value": number}` | 最后一步 |

## 测试指标

| 读法 | Spearman ρ（95% 区间） | Pearson r | MAE | 中位延迟 | 峰值显存 |
| --- | --- | ---: | ---: | ---: | ---: |
| 只训指针头 | 0.824 [0.808, 0.837] | 0.841 | 9.27 | 209 ms | 1,973 MB |
| 语言 LoRA + 指针头，最后一步 | 0.896 [0.886, 0.905] | 0.905 | 7.04 | 406 ms | 2,902 MB |
| 语言 LoRA + 指针头，第 900 步 | 0.895 [0.885, 0.904] | 0.905 | 7.27 | 410 ms | 2,008 MB |
| 4-bit QLoRA，生成 JSON | 0.902 [0.892, 0.910] | 0.913 | 6.78 | 1,374 ms | 1,909 MB |

1,658 张测试图的覆盖率和 schema 合法率都是 1.0。区间是按 `group_id` 的 cluster bootstrap，2,000 次，种子 42。这份切分里每张图自己是一组。

Spearman 的配对差（指针读出减去对照）：

- 最后一步 LoRA + 指针头 减 JSON QLoRA：**−0.006** [−0.010, −0.003]
- 第 900 步 减 最后一步：**−0.001** [−0.003, +0.001]
- 最后一步 LoRA + 指针头 减 只训指针头：**+0.072** [+0.062, +0.083]

最后一步指针头的中位延迟是 406 / 1,374 ≈ 0.30，大约比 JSON 生成快 3.4 倍。第 900 步的峰值显存是训练结束后的评测进程，不是更小的模型。

## 怎么读这些数字

只训指针头、骨干冻结时，已经明显好于未训练的 logits 读出（早先 120 张验证图上 ρ 0.851 对 0.549）。剩下接近 JSON QLoRA 的那一截，主要来自语言 LoRA，不是来自把分数解码成文字。

LoRA 加指针头的训练损失不是平稳下降的（第 1 步大约 1.30，第 976 步大约 1.47）。验证监控的最低点在第 900 步（256 张上交叉熵 1.361；全部 1,660 张上 1.344）。这份权重没有提高测试集排序。差值的区间包含零。

视觉 merger 只做了一张图的一次反向探针。峰值占用 4,046 MB，卡的总量是 4,096 MB，所以没有训这一步。
